# FullBuff Buff Sets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the player keep several named buff sets (one pick per conflict slot plus tracked burst items), edit them in the options, and see in the popover only what from the active set is missing.

**Architecture:** The pipeline turns stacking groups into named **slots** (cross-category merges from `curated.yaml`, emitted as `Data/Slots.lua`). New Engine modules `Bags` (bag counts), `Sets` (per-character set storage, CRUD, spec binding) and `SetTracker` (rows for a set) feed a rewritten Popover (stats + flat set list + burst block) and a new "Sets" section in the Options panel; MaxCalc accepts the set's picks instead of recommendations.

**Tech Stack:** Python 3.12, pytest, pyyaml, lupa (Lua 5.1); WoW Lua addon API (Interface 16001), `C_Container`.

**Spec:** `docs/superpowers/specs/2026-10-13-fullbuff-sets-design.md` (builds on `docs/superpowers/specs/2026-10-13-fullbuff-design.md`)

## Global Constraints

- Slot = stacking group: the build sets `excl = <slot id>` for merged groups; MaxCalc and the editor use the same `excl`.
- Pipeline order: extract → curated → camping → **slots** → questie sources → craft sources → acquisition levels → emit.
- `Data/Slots.lua` shape: `ns.Slots = { [slotId] = { name = { en = "...", uk = "..." }, order = N } }`; generated header `-- GENERATED by tools/build.py. Do not edit.`
- Burst buffs (`burst = true`) are never in slots, never in the maximum, tracked only by bag count.
- Storage in `FullBuffCharDB`: `sets[setId] = { name, picks = {[slotId] = buffId | false}, burst = {buffId,...}, spec = nil|1|2|3 }`, `activeSet`, `nextSetId`; `false` = "not used", absent = empty.
- First load with no sets → "Main" (en) / "Основний" (uk) from recommendations, active.
- At most one set per spec binding.
- Saved picks with unknown buff/slot ids are kept and shown UNAVAILABLE; never auto-deleted.
- Set row statuses: `ACTIVE`, `MISSING`, `UNAVAILABLE`; order ACTIVE, MISSING, UNAVAILABLE, then slot `order`.
- `missingCount` = MISSING rows + tracked burst with bag count 0; UNAVAILABLE not counted.
- Popover: no categories, no "show only missing"; `ns.DB.onlyMissing` and `ns.DB.hiddenCats` removed (defaults, options, view model).
- Strings in `Locales/enUS.lua` and `Locales/ukUA.lua` (real Ukrainian, no Russian; parity and Cyrillic tests stay green). Lua texture paths with doubled backslashes. No secure templates, protected calls, OnUpdate polling.
- Durations, reminders, import/export, account-wide sets: out of scope.

## Review Focus

1. **Saved set refers to a buff/slot that disappeared after a data rebuild** — kept, shown UNAVAILABLE, no Lua error; tested in Task 4.
2. **Deleting the active set or the last set** — another set becomes active / "Main" is recreated; tested in Task 3.
3. **Binding a second set to a spec that is already bound** — the old binding is cleared; tested in Task 3.
4. **Empty set (every slot empty or "not used")** — popover shows the empty-set line with an options button, badge 0, max equals current; tested in Tasks 4 and 5.
5. **`C_Container` missing or returning nil items** — counts 0, no error; tested in Task 2.

### Task 1: Pipeline slots and `Data/Slots.lua`

**Files:**
- Create: `tools/slots.py`, `tools/tests/test_slots.py`
- Modify: `tools/curated.yaml` (new `slots:` section), `tools/build.py` (call order), `tools/emit_lua.py` (`emit_slots`, report section), `addon/FullBuff/FullBuff_Forever.toc` (add `Data\Slots.lua` after `Data\Weights.lua`)
- Regenerate: `addon/FullBuff/Data/*.lua`

**Interfaces:**
- Produces: `apply_slots(buffs: dict[int, Buff], cur: dict) -> tuple[dict[str, dict], list[str]]` returning `(slots, warnings)` where `slots[slotId] = {"name": {"en": str, "uk": str}, "order": int}`; `emit_slots(slots, path)`.

Rules: each `slots:` entry `{id, name: {en, uk}, groups: [excl keys]}` sets `excl = id` on every buff (all categories) whose current `excl` is in `groups`; a group matching no buff → warning `slot <id>: group <g> matches no buff`. Every remaining non-burst buff's `excl` becomes its own slot with an automatic name: FLASK → Flask/Фласка; WEAPON → Weapon/Зброя; `FOOD:Well Fed` → Food/Їжа; `ELIXIR:<STAT>` → "Elixir — <stat>" / "Еліксир — <стат>"; `SCROLL:<STAT>` → "Scroll — <stat>" / "Сувій — <стат>"; any other key → the name of the lowest-id buff in the group (same text for en and uk). Stat names en/uk dictionary for the canonical stat keys lives in `tools/slots.py`. `order` = category order (`CLASS WORLD CAMPING FLASK ELIXIR FOOD SCROLL WEAPON QUEST TRINKET POTION`, using the lowest-category member) then en name. Initial `slots:` content = the spec §2 table (Intellect, Stamina, Spirit, Strength; the four already-merged class/camp groups only get names: Attack power, Mana regeneration, All stats %, All stats); look up the exact existing `excl` keys in `addon/FullBuff/Data/Buffs.lua`.

### Task 4: `Engine/SetTracker.lua` and MaxCalc picks

**Files:** Create `addon/FullBuff/Engine/SetTracker.lua`, `tests/lua/test_settracker.py`; Modify `addon/FullBuff/Engine/MaxCalc.lua`, `tests/lua/test_maxcalc.py`, TOC (after Sets).

**Interfaces:**
- Consumes: Catalog entries (`id, excl, status, fx, burst, rankSpell`), `ns.Buffs`, `ns.Slots`, `ns.Bags:CountBuff`, `ns.ViewModel.FormatFx`, `ns.ViewModel.IconFor`.
- Produces: `ns.SetTracker:Evaluate(state, catalog, set) -> { rows = {{slot, buffId, name, icon, valueText, status, bagCount}}, burst = {{buffId, name, icon, bagCount}}, missingCount, unavailableCount }`; `ns.MaxCalc:Compute(state, catalog, picks)` — with `picks`, the chosen entry per `excl` is the catalog entry whose id equals `picks[excl]` when its status is ACTIVE or CAN_ADD and not burst; `false`/absent → no chosen entry; without `picks` unchanged.

Status rules: ACTIVE if the catalog entry is ACTIVE; MISSING if CAN_ADD; UNAVAILABLE if the buff id is not in `ns.Buffs`, has no catalog entry, or the entry is UNAVAILABLE. Name for a vanished buff: `"#" .. buffId`. Order ACTIVE, MISSING, UNAVAILABLE, then `ns.Slots[slot].order` (unknown slot last), then name.
